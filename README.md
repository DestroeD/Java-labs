# Лабораторна робота №3
**Тема:** Токен-сервіс, фільтр/інтерцептор та кастомна анотація (Java, Maven)

---

## 1. Загальний опис

Проєкт реалізує простий токен-сервіс без використання Spring.  
Основна ідея — змоделювати:

- генерацію токена при "реєстрації/авторизації";
- перевірку, оновлення та інвалідацію токена;
- фільтр (інтерцептор), який перевіряє токен перед викликом ендпойнта;
- кастомну анотацію, що обмежує доступ до ендпойнта тільки при наявності валідного токена;
- юніт-тест для логіки генерації токена;
- логування українською мовою.

---

## 2. Структура проєкту

Основні пакети:

- `com.example.lab3`
    - `App` (або `Main`) — точка входу, демонстрація роботи сервісу.
- `com.example.lab3.token`
    - `TokenPayload` — модель даних токена.
    - `TokenService` — сервіс генерації, перевірки, оновлення та інвалідації токенів.
- `com.example.lab3.security`
    - `Request` — спрощена модель HTTP-запиту (заголовки + атрибути).
    - `TokenRequired` — кастомна анотація для захищених ендпойнтів.
    - `TokenFilter` — "фільтр/інтерцептор", який перевіряє токен перед викликом методу.
- `com.example.lab3.controller`
    - `AuthController` — "контролер" із ендпойнтами реєстрації, логіну, інвалідації та доступу до профілю.

Тести:

- `com.example.lab3.token.TokenServiceTest` — юніт-тест для `TokenService`.

## 3. Формат токена та логіка генерації

Генерацією токена займається клас `TokenService`.

Токен містить такі дані:

- **ім'я користувача** (`username`);
- **назва застосунку** (`appName`);
- **час створення** (`issuedAt`);
- **час закінчення дії** (`expiresAt`).
